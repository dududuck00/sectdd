# SecCodeBench external partitioned experiment v1

This is the P1 realistic external validation selected from the review's alternatives (coverage intervention OR external validation). The separate coverage-intervention proposal is not executed and must not be described as an experiment result.

Upstream: SecCodeBench v2.2.0, all 13 Python projects screened using prompts, test structure and execution requirements before any model output. Two SSRF projects require live public HTTP endpoints for their functional oracle; the offline sandbox cannot reproduce those unchanged tests. TorchLoad has only one security test and cannot provide an independent visible/hidden security partition. These three are retained in the eligibility record and excluded from the partitioned analysis, leaving ten tasks. This is an explicitly scoped Python project experiment, not the complete 98-task benchmark or official leaderboard score.

For each eligible task, expose the first upstream security test function in source order and its statically required helpers. Keep every other upstream security test hidden. Author one new functional visible test from the public prompt; retain all upstream functional tests as hidden. Shared upstream fixtures are dependencies, not additional test cases. This splitting rule precedes generation and is not outcome-driven. A source-order split alone does not establish behavior-family independence: report overlap, especially among deserialization/SSTI exploit variants. The independent upstream test authorship claim applies to upstream tests; visible functional tests are newly author-written.

Methods: B0 requirement only; B3 visible functional and security tests upfront; M B0 plus at most two structured visible-failure revisions; B6 B3 plus the same revision policy. B0/M and B3/B6 share byte-identical initial responses. Stop on visible suite pass or three total calls. Use both complete local Qwen2.5-Coder 7B/14B checkpoints, seeds 261001/261021/261051/261057/261091, temperature .2, output ceiling 4096 per call, feedback ceiling 600 per revision, context capacity 32768. These are project-context budget adaptations; report them and actual tokens. No external hidden result enters prompts or stopping.

Primary comparisons B3-B0, M-B0, B6-B3. Report final hidden joint/function/security outcomes, task-cluster bootstrap intervals (10000; seed 20260910), paired repairs/regressions, opportunities and actual costs. Ten tasks define the inference units; models and slots remain clustered. Holm across the three primary joint tests. Results do not establish cross-family or multilingual generalization.

Candidate code runs with complete upstream src scaffold, original dependency declarations and isolated writable project copies, no host/project/home mount, no external network. Only the selected test partition is mounted per evaluation. Official security tests using a local HTTP server may run inside the isolated network namespace. A changed runtime, test, prompt or inclusion rule after generation requires a recorded amendment and must not be silently combined.

Before generation, qualify visible and hidden execution with the original supplied project subject and an independently written safe subject where available; record whether the supplied subject is vulnerable, a stub or safe rather than assuming it is ground truth. Qualification results and any test ambiguity remain separate from model results. Independent human review remains a distinct task; do not infer it from machine validation.
