# Matched-information specification representation experiment

Status: protocol and all prompt pairs must be frozen before any generation. This is a post-primary study on previously observed tasks, not a fresh generalization set.

## Question and estimand
Does expressing the same visible behavioral information as executable Python test bodies change hidden functional/security joint success relative to operational prose? Cross representation (code, prose) with specification content (functional, functional plus security). All 12 SALLM/CodeGuard+ tasks from the upfront factorial are included, two Qwen2.5-Coder models (7B, 14B), five fixed seeds: 480 new single-call trajectories. No historical generations are substituted for an arm.

Both arms receive the identical requirement, system message, visible case identifiers/descriptions, and fixture/helper source. Code contains the original selected test bodies; prose translates every action and assertion, preserving concrete strings, byte/text distinctions, API operations, equality versus containment, and cleanup. Setup, teardown, helper methods, imports and class definitions are byte-identical shared context. Tests are interpreted in that context, with setup/cleanup applied separately for each test. Security-only test bodies are omitted from both functional arms. Common fixtures can include security-related setup: the representation contrasts are controlled within each content level, but the content contrast is not an estimate of removing all security cues.

This isolates test-body representation conditional on shared executable environment scaffolding. It does not compare a completely code-free prompt with a code prompt, nor show that executing tests is itself beneficial: neither arm receives execution feedback. Literal information is matched, not token length. Prompt and output tokens are reported; all input is delivered without truncation. Prose is AI-authored and checked against source before freezing; no independent human semantic review is claimed. The translation ledger includes source bodies beside prose for all 24 cases.

## Generation and scoring
Temperature 0.2, one call, max output 3072 tokens, context 32768, BF16 local checkpoints, seeds 151001/151021/151051/151057/151091. Prompt order is counterbalanced by a fixed shuffle, applied before generation; task/model/seed are pairing keys, not shared initial candidates. Use the existing visible and hidden partitions and original isolated evaluators. Score only the final candidate; never supply hidden tests or outcomes to generation. Generation responses are persisted before evaluation so an evaluation interruption does not cause resampling. Syntax/import errors and token-limit completions remain outcomes. Transport failure is an incomplete cell, not an excuse to drop it; resume the same cell without altering prompts or budgets.

## Frozen analysis
Primary outcome: hidden joint pass. Secondary: hidden functional and security pass, by-task and by-model outcomes, actual prompt/output tokens. Three planned contrasts: code minus prose with functional content; code minus prose with both contents; interaction (code-minus-prose with both) minus (code-minus-prose with functional). Resample the 12 tasks 10000 times, preserving every model/seed in a cluster; percentile 95% intervals. Exact two-sided task-level sign flips with Holm correction across the three joint contrasts. No cell-level significance test; task symmetry is the null assumption. Report all contrasts regardless of sign. Require complete 480-cell grid before inference. No success-dependent stopping or prompt revision after generation.
