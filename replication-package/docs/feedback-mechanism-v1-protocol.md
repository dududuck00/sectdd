# Fixed-call feedback mechanism experiment v1

Specified after review of arXiv v2 and the later balanced experiment, before new revision calls. Historical records remain unchanged. This is a mechanistic addendum, not an independent replication or fresh holdout claim.

Population: all 20 balanced primary tasks, both locally available Qwen2.5-Coder 7B and 14B checkpoints, all five original request slots. No selection based on hidden outcomes or initial failure. The 200 archived B0 responses are shared across six branches (1,200 new trajectories; 2,400 new revision calls). Archived generation itself is not counted as new inference.

Every branch receives exactly two revision calls, including initially passing code. Identical original requirements, initial response, request seeds, temperature 0.2, per-call output ceiling 3,072 tokens, feedback ceiling 600 tokens and context capacity 32,768. Actual prompt lengths and generated tokens can differ and must be reported; equal ceilings do not imply equal realized cost. Context overflow or infrastructure failure is an incomplete run, never an outcome silently excluded. This fixed-call protocol is distinct from the paper's natural stopping policy and its 14,000 total-input-token ceiling.

Branches: blind self-revision (no execution status); binary suite PASS/FAIL; stable-ID top-two raw failures; security-priority top-two raw failures; stable-ID top-two structured failures; security-priority top-two structured failures. The last four cross selection/order and rendering. Raw and structured use the same last 12 failure lines; structured additionally supplies case ID, marker and executable property, so its estimand includes metadata, not typography alone. Priority matches M's security-first, less-seen-first, ID tie-break. With at most two failures, set selection often has no opportunity; measure order separately. Passing branches receive PASS and a revision request, except blind which always receives exactly the same request. No hidden feedback.

Primary estimands: binary minus blind; fixed_raw minus binary; priority_raw minus fixed_raw; fixed_structured minus fixed_raw; rendering-by-selection interaction. Outcome: final hidden joint success, with functional/security outcomes and initial-to-final regressions also reported. Task-cluster bootstrap (10,000 samples; fixed analysis seed), keeping both models and all five slots within task; report paired wins/losses and intervals. Correct the five planned joint contrasts together using Holm over task-level paired sign-randomization p-values. Other comparisons are descriptive. Never interpret non-significance as equivalence.

Record every feedback round, full and delivered token lengths, truncation, chosen IDs, counterfactual selector IDs under the same pre-round seen counts, actual model usage and timing. Opportunity-conditioned analyses are descriptive: later-round eligibility is post-treatment. Initial-round opportunity can be compared on a common population.

Validation: control information leakage and crossed selection/representation unit checks, one sandbox adapter check per benchmark, server checkpoint identity and full frozen grid. Run generation only after the input freeze exists. Final hidden execution occurs after both calls and final candidate freezing. Existing hidden tests are reused solely for a post-primary comparison, not presented as newly unseen by investigators.
